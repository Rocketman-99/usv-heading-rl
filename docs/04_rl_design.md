## 1. 문제 정의

RL 이 푸는 문제는 **제어가 아니라 튜닝**이다.

| | 값 |
|---|---|
| 행동 (action) | PID 게인 (Kp, Ki, Kd) — 타각이 아님 |
| 에피소드 | 게인 1조로 폐루프 시뮬레이션 1회(또는 복수 조건) 실행 |
| 보상 | 그 시뮬레이션의 성능 지표를 묶은 스칼라 |
| 관측 (observation) | `[작업자 결정 필요]` — 아래 2절 참조 |

이 구조에서 문제는 사실상 **문맥 없는 최적화(contextual bandit / black-box optimization)** 에
가깝다. 이 점을 인지하고 알고리즘을 고르면 설명이 쉬워진다.

## 2. 관측 설계 — `[작업자 결정 필요]`

| 선택지 | 의미 | trade-off |
|---|---|---|
| (a) 상수 관측 | 게인을 조건 무관하게 하나로 찾음 | 가장 단순. 사실상 최적화. "왜 RL 인가" 질문을 받음 |
| (b) 플랜트 파라미터 (K, T) | 플랜트가 바뀌면 게인도 바뀜 | 게인 스케줄링에 가까움. 2단계 이후 의미 생김 |
| (c) 운항 조건 (속력, 외란 세기) | 조건별 게인 | 3단계와 직접 연결. 학습 부담 증가 |

> 참고: HANDOFF 2장의 문제의식("조건이 바뀌면 처음부터 다시 맞춰야 한다")에
> 정면으로 답하는 것은 (c) 다. 다만 1단계에서 (c) 를 하려면 조건 변화가 있어야 하는데
> 1단계 플랜트는 고정이다. 1단계는 (a) 로 파이프라인을 완성하고,
> 3단계에서 (c) 로 확장하는 순서가 단계 구조와 맞는다.

### 3.1 항 구성

평가 지표 4개를 어떤 형태로 묶을지 정한다.

```
R = − ( w1 · f1(침로 오차 RMS)
      + w2 · f2(정정 시간)
      + w3 · f3(오버슈트)
      + w4 · f4(러더 사용량) )
```

정해야 할 것:

- [ ] 각 항의 정규화 방법 (단위와 크기가 다르다. 베이스라인 PID 값으로 나누는 방법이 흔하다)
- [ ] 가중치 w1 ~ w4
- [ ] 실패 조건과 페널티 (발산, 정착 실패 등)
- [ ] 항의 형태 (선형 / 제곱 / 로그)

## 4. 알고리즘 — `[작업자 결정 필요]`

| 후보 | 적합성 | 비고 |
|---|---|---|
| PPO | 연속 행동, 안정적, RL Toolbox 지원 | 관측이 상수면 과한 선택 |
| DDPG / TD3 | 연속 행동 | 샘플 효율 좋으나 튜닝 민감 |
| Bayesian optimization | 이 문제 구조에 가장 맞음 | "강화학습 프로젝트"라는 포지션과 어긋남 |
| CMA-ES 등 진화 전략 | 블랙박스 최적화에 강함 | 위와 같은 문제 |

> 알고리즘 선택 자체가 면접 질문이 된다.
> "왜 RL 인가, 베이지안 최적화가 더 맞지 않나"라는 질문에 대한 답을 준비해 둘 것.
> 정직한 답은 3단계(조건별 게인)까지 가면 RL 구조가 의미를 갖는다는 것이다.
