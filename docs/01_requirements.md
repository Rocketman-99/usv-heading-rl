# 01. 요구사항 및 범위 정의

이 문서는 HANDOFF.md 1~4장을 기반으로 작성한 초안이다.
판단이 필요한 항목은 `[작업자 결정 필요]` 로 비워 두었다.

---

## 1. 목적과 포지션

**목적**: 취업 포트폴리오 (2026 하반기 공채, 방산·조선·자동차 설계/R&D 직무)

**대상**: 무인수상정(USV)의 침로 제어

**핵심 주장**: 사람이 시행착오로 맞추던 제어 게인을 정량적 절차로 최적화하고,
그 결과가 신뢰할 만한지를 검증한다.

**포지션**
최종 제어기는 검증 가능한 PID다. 강화학습은 제어기를 대체하지 않고
**게인을 찾는 최적화 도구**로만 쓴다.

이 포지션이 갖는 실무적 의미:

- 인증·심사 관점에서 최종 산출물이 4개 실수(K_p, K_i, K_d)이므로 검증 가능하다
- 학습이 실패해도 베이스라인 PID 라는 동작하는 제어기가 남는다
- "AI 가 조종한다"가 아니라 "AI 로 튜닝 공수를 줄인다"는 주장이므로 방어 가능하다

## 2. 해결하려는 문제

작업자는 드론, UAM(eVTOL), 수중로봇 세 프로젝트에서 제어 게인을 시행착오로 튜닝했다.
공통 한계는 두 가지다.

1. 조건이 바뀌면 처음부터 다시 맞춰야 한다
2. 왜 그 값이 좋은지 정량적으로 설명하기 어렵다

특히 UAM 사례에서는 1회 비행당 천이 시도가 3~5초에 불과해
파라미터와 결과의 상관을 판단할 시행 횟수 자체를 확보하지 못했다.

→ **시뮬레이션에서 시행 횟수를 확보하고, 좋은 게인의 기준을 수식으로 고정한다.**
   이 프로젝트가 하려는 일은 이것이다.

## 3. 기술 스택 및 환경

`matlab/src/checkEnv.m` 을 실행해 얻은 결과다.
**Claude Code 는 이 값을 추측해 채우지 않는다.**

| 항목 | 설치 | 라이선스 | 버전 | 확인일 |
|---|---|---|---|---|
| MATLAB | — | — | **R2023b (23.2)**, win64 | 2026-08-07 |
| Simulink | ✅ yes | ✅ yes | 23.2 | 2026-08-07 |
| **Reinforcement Learning Toolbox** | ❌ NO | ❌ **NO** | — | 2026-08-07 |
| Control System Toolbox | ❌ NO | ✅ yes | — | 2026-08-07 |
| Deep Learning Toolbox | ❌ NO | ✅ yes | — | 2026-08-07 |
| Optimization Toolbox | ❌ NO | ✅ yes | — | 2026-08-07 |
| Statistics and ML Toolbox | ❌ NO | ✅ yes | — | 2026-08-07 |

읽는 법:

- **설치 NO / 라이선스 yes** — 라이선스에는 포함되어 있으나 설치만 안 된 상태.
  MATLAB 홈 탭 → 애드온 → 애드온 탐색기에서 설치하면 바로 쓸 수 있다.
- **설치 NO / 라이선스 NO** — 라이선스 자체에 없다. 구매 또는 체험판이 필요하다.
  → **RL Toolbox 가 여기 해당한다. 이 프로젝트의 학습 환경 결정(D-002)을 좌우한다.**

⚠ `license('test', ...)` 는 설치 여부와 무관하게 라이선스 파일만 조회한다.
확정하려면 애드온 탐색기에서 "Reinforcement Learning Toolbox" 를 검색해
`설치` 버튼이 뜨는지(라이선스 있음) `평가판 받기 / 구매` 가 뜨는지(없음) 확인할 것.

**결정: 1단계는 Python 으로 진행한다** (`decisions.md` D-002b, 2026-08-07).

RL Toolbox 라이선스 부재가 직접적인 계기였지만, 결정적 이유는 따로 있다.
개발 환경(컨테이너)에 MATLAB 이 없어 **AI 에 위임한 코드를 검증할 수 없었다.**
실제로 처음 작성한 MATLAB 코드 600줄은 한 번도 실행되지 않은 채 커밋됐고,
Python 으로 옮겨 pytest 70개를 붙이자 4개가 실패했다 (1건은 실제 이해 오류).

- 나오는 숫자의 품질: 두 환경이 같다 (같은 IEEE 754, 같은 LAPACK)
- 결과가 옳다고 확신할 수 있는 정도: Python 이 낫다 (반복 검증 비용)
- 2단계는 재검토한다 — 3자유도 모델 구조 검증에서는 Simulink 가 유리하고,
  조선·방산 채용에서 MATLAB/Simulink 의 신호값도 유효하다

MATLAB 구현은 `matlab/` 에 보류 상태로 남겨 두었다 (`matlab/README.md`).

**참고: RL Toolbox 없이도 막히지 않는다**

이 프로젝트에서 RL 이 푸는 문제는 행동이 (Kp, Ki, Kd) 3차원 실수이고
1단계에서는 관측이 상수다. 상태 전이가 없는 블랙박스 최적화에 가까워
리플레이 버퍼·타깃 네트워크·GAE 같은 기능이 필요하지 않다.

**Control System Toolbox 는 설치해 둘 것** (라이선스 보유, 설치만 하면 됨)

베이스라인 PID 수동 튜닝의 근거를 쓰는 데 유용하다. `tf`, `step`, `margin`,
`rlocus` 로 플랜트 `K/(s(1+Ts))` 의 위상여유를 보면서 게인을 고르면
D-005 의 "왜 그 값인가"를 정량적으로 설명할 수 있다.
자동 튜닝(`pidtune`)을 쓰라는 뜻이 아니다 — HANDOFF 9장 금지 사항이다.
어디까지나 **수동 튜닝의 근거를 설명하기 위한 분석 도구**로만 쓴다.

## 4. 단계별 범위와 완료 조건

각 단계는 그 시점에서 멈춰도 완결된 결과물이 남도록 설계되어 있다.
단계를 건너뛰거나 병합하지 않는다.

### 1단계 — Nomoto 파이프라인 (2~3주)

| 항목 | 내용 |
|---|---|
| 플랜트 | 1차 Nomoto `T·ṙ + r = K·δ` |
| 파라미터 | 문헌 표준 선형 값 (출처 명시) — `02_plant_model.md` |
| 산출물 | 베이스라인 PID vs RL 최적화 게인 성능 비교표 |
| 완료 조건 | 비교표가 나오고, **학습에 쓰지 않은 초기조건에서도 재현**될 것 |

- [x] 파라미터 출처 문서화 및 재유도 검증

- [ ] 보상 함수 설계 — 작업자 직접
- [ ] 학습 루프 구성
- [ ] 미학습 조건 재현 확인

### 2단계 — 3자유도 모델 교체 (4~6주)

플랜트만 교체하고 1단계 파이프라인을 재사용한다.

- `M·ν̇ + C(ν)ν + D(ν)ν = τ`, `ν = [u, v, r]`
- 유체력 미계수는 공개 문헌의 표준 선형 데이터 (출처 명시)
- **학습 전에** 선회권 시험·Z자 조종시험을 재현해 모델 타당성을 먼저 확인
- 완료 조건: 모델 타당성이 문헌 값과 정성적으로 일치 + 3자유도에서도 RL 게인이 베이스라인 초과

### 3단계 — 외란 강건성 비교

- 파랑·조류를 τ 에 외력/모멘트로 인가
- 외란 조건별 게인 성능 비교
- 완료 조건: 외란 세기별 성능 저하 곡선 + 학습/미학습 조건 성능 차이표

## 6. 검증 요구사항

"학습이 잘 됐다"만으로는 채택하지 않는다 (HANDOFF 8장).

1. **베이스라인 대비 비교** — 동일 조건에서 수동 튜닝 PID 와 비교. 비교표 필수
2. **미학습 조건 재현** — 학습에 쓰지 않은 초기 침로/목표값/외란 크기에서 성능 유지 확인
3. **구동기 거동 확인** — 지표가 좋아도 타각이 진동하면 채택하지 않는다. 시간 응답 그래프 필수
4. **재현성** — 랜덤 시드를 바꿔 반복. 시드 하나로 결론 내지 않는다

세부 조건(어떤 초기 침로, 몇 개 시드, 어떤 외란 크기)은 `[작업자 결정 필요]`.
확정 시 `05_validation.md` 에 기록.
